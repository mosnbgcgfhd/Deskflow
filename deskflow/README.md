# DeskFlow — V1 Project Scaffold

Business Operations Desktop Platform (Flutter Windows + Supabase).

This is a working code scaffold reflecting the architecture decisions made
during design review. It is **not** a compiled `.exe` — see "What's not
included" below for what you still need to run locally.

## Decisions locked in for this build

| Decision | Choice | Why |
|---|---|---|
| Business model | Real SaaS product, sold to multiple companies | Drives every isolation/security choice below |
| Backend | Supabase (Postgres + Auth + Realtime + Storage) | RLS gives clean multi-tenant isolation; mature ecosystem |
| Multi-tenancy | Row Level Security keyed on `organization_id` | Company B can never query Company A's rows, enforced in the DB itself, not just app code |
| Roles | 3 fixed roles: `admin` / `manager` / `employee` | Simpler to ship; dynamic/custom permissions deferred to V2 |
| Realtime | Enabled everywhere (tasks, projects, activity_log, notifications) | Live Kanban board, live dashboard, live activity feed, live notification bell |
| Notifications | In-app only | Native OS / system-tray push needs a background service — deferred to V2 |
| Offline mode | Not included | Deferred to V2 |

## How to actually run this

1. **Create a Supabase project** at supabase.com, then open the SQL editor
   and run `supabase/migrations/001_initial_schema.sql`. This creates every
   table, the RLS policies, and turns on Realtime for the right tables.

2. **Drop your project credentials in**
   `flutter_app/lib/core/constants.dart` (`SupabaseConfig.url` and
   `.anonKey`, found under Project Settings → API in Supabase).

3. **Generate the native Windows platform folder.** This scaffold ships
   only the Dart/`lib/` source — the native `windows/` runner folder is
   generated by the Flutter SDK itself and can't be produced without it.
   From inside `flutter_app/`:
   ```
   flutter create --platforms=windows .
   flutter pub get
   flutter run -d windows
   ```

4. **Create your first organization** from the app's "Create your
   organization" link on the login screen — the account that does this
   automatically becomes that org's Admin.

## What's not included in this scaffold (by design, per the plan)

- Compiled `.exe` / Windows installer — build it yourself with
  `flutter build windows` once step 3 above is done.
- Native OS notifications, offline mode, dynamic/custom permissions —
  all explicitly deferred to V2 per the design review.
- Billing/Stripe integration — flagged as an open question, not yet designed.
- The marketing website (`deskflow.app`) — separate project, not part of
  this Flutter app.
